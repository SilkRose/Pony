# APIdle

## Synopsis:
An idle game where you play by writing code to interact with an API.

## Ideas:
- Resource collected is data. (Singular datum)
- Rate limited at the start, buy upgrades to increase this.
- Endpoints are unlocked over time.
- Docs are served locally via the web-server, and are tied to your save.
- Each building could have a mini-game themed around it.
- Game will be designed to be automated.
- Have 20 buildings. (10 recycling, 10 generative)
- Either a custom engine or use the Bevy game engine.
- Prestige/ascension could be archive tapes.
- Player must send random data with the mane 'click' requests.
- Data is capped. You must buy hard drives to increase how much you can have.
- Hard drives can be upgrades to store more data.
- Destroy hard drives to get bonus or upgrade?
- Challenges endpoint: solve programming challenges to earn temporary boosts.
- Maybe each building itself could be a coding challenge?
- 

## Building Ideas:
- Data Race: a seeded race between two datum's?
- Data Broker: A shady guy who turns datum's into more datum's.
- Data Farm: A seeded growth algorithm making datum's bigger?
- Archive: Ages datum's like wine, making them more valuable.
- Data Bank: store data letting it accrue interest.
- Database: store data in an organized manner.
- Data Scraper: scrapes data from the internet?
- 52!: shuffles a deck of cards and converts the output into datum's.
- Hash Function: hashes your datum's and converts the output into more datum's.
- /dev/random: generate data from randomness.
- Data-mine, data-dump, data breach?
- 

## Upgrade Ideas:
- Compiler/interpreter version upgrades.
- Different programming concepts?
- Different math formulas?
- Unlock higher rate limits?
